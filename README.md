⚠️ Внимание. Приложение уязвимо специально. Запускайте его только локально (127.0.0.1) и никогда не выкладывайте в интернет. Эксплуатируйте уязвимости только в собственных учебных проектах.

Что внутри

app.py	Уязвимое веб-приложение (форма входа и гостевая книга) на http.server и sqlite3
exploit.py	Скрипт, который эксплуатирует уязвимости
fix.diff	Патч, исправляющий обе уязвимости

Внешние библиотеки не нужны, достаточно Python 3.8+.

Уязвимости

Обе относятся к категории A03:2021: Injection из OWASP Top 10.

SQL Injection (форма входа /login). SQL-запрос собирается склейкой строк, поэтому через поля логина и пароля можно подставить собственный SQL-код. Результат: обход аутентификации и утечка пароля администратора через UNION SELECT.
Stored XSS (гостевая книга /comment). Комментарии выводятся на страницу без экранирования, и сохранённый скрипт выполняется у каждого, кто откроет страницу.
Запуск
bash
# 1. Запустить приложение
python app.py
# откройте http://127.0.0.1:8000

# 2. В другом терминале запустить атаку
python exploit.py

exploit.py выполняет:

вход как admin'-- (обход проверки пароля);
вход через условие ' OR '1'='1;
извлечение пароля администратора через UNION SELECT;
отправку комментария с <script> и проверку, что он вернулся без экранирования.
Исправление

Патч применяется к app.py:

bash
git apply fix.diff

Что меняет патч:

SQL-запрос становится параметризованным (WHERE username=? AND password=?), данные пользователя больше не попадают в SQL-код;
пользовательский текст экранируется через html.escape() перед выводом в HTML;
подробные тексты ошибок SQL заменены на общее сообщение.

После патча повторный запуск exploit.py показывает, что все атаки блокируются.
